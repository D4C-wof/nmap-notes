# 10 · 授权与合规

> **本章目标**：让你在按下回车之前，能说清楚"我凭什么扫这个目标"。
>
> 这一章不是免责声明。它是**技术流程的一部分**：没有授权的扫描，在技术上再漂亮也是事故。

## 10.1 一句话原则

> **端口扫描在法律上通常被认定为"侵入计算机信息系统"的实行行为，而不是"准备工作"。**
>
> 也就是说：**你不需要"扫出东西"才违法，扫这个动作本身就够了。**

这个判断在多数司法辖区成立，包括中国、美国、欧盟主要国家。区别只在量刑与是否自诉。

## 10.2 什么算"有授权"

### 10.2.1 不够的（常见误区）

| 你以为的授权 | 为什么不够 |
| --- | --- |
| "这是公网 IP，谁都能访问" | 公网可达 ≠ 允许扫描。可访问是"允许正常请求"，不是"允许探测" |
| "我是这家公司的员工" | 员工身份不覆盖"超出岗位职责的探测"。多数公司内网扫描也需安全团队批准 |
| "客户口头说可以" | 口头授权在争议时无法举证。**必须有书面记录** |
| "我在做众测，平台上有这个目标" | 平台 scope 有边界（子域、端口、时间窗、禁止项）。超范围即违规 |
| "扫描不算攻击" | 见 10.1。多数法域的执法与司法实践不这么认为 |
| "我只扫了一个端口" | 数量不影响定性，只影响量罚 |

### 10.2.2 够的（最低标准）

一份可用的授权，至少要说清六件事：

| 要素 | 说明 | 缺失后果 |
| --- | --- | --- |
| **授权主体** | 谁有权授权（必须是资产所有者或其书面委托人） | 授权无效 |
| **目标范围** | 精确到 IP / 域名 / 端口 / 协议；网段要写 CIDR | 超范围即违规 |
| **排除项** | 明确不能碰的资产（生产库、支付、第三方托管） | 一旦碰到就是事故 |
| **时间窗口** | 起止时间，是否允许非工作时间 | 窗口外扫描违约 |
| **允许的技术手段** | 是否允许版本探测、脚本、UDP、全端口 | 手段超限违约 |
| **速率与影响约定** | 最大速率、可否导致服务降级、出事联系人 | 造成业务中断时责任不清 |

### 10.2.3 建议再加三条

| 要素 | 为什么 |
| --- | --- |
| 数据处理条款 | 扫到的信息（banner、证书、主机名）算不算敏感数据，能不能存、存多久 |
| 报告与披露方式 | 漏洞怎么报、报给谁、多久内必须报 |
| 出口 IP 声明 | 把你的扫描源 IP 报备给对方，便于对方加白名单、避免误判为攻击 |

## 10.3 高风险技术的专门授权

以下操作**不能靠一句"允许测试"覆盖**，必须单独写明：

| 技术 | 为什么需要专门授权 | 可能后果 |
| --- | --- | --- |
| `-sU` 大范围 UDP 扫描 | 流量大、易触发告警 | 被判定为 DoS 尝试 |
| `-p-` 全端口 | 侵入性明显更高 | 服务/网络设备负载上升 |
| `--script` 中 `brute` 类 | 会产生大量失败登录 | **账号锁定、运维被锁在门外** |
| `--script` 中 `dos` / `fuzzer` 类 | 设计目的就是压测/打崩 | 服务中断 |
| `--script` 中 `exploit` 类 | 可能改变目标状态 | 写入文件、创建账号、服务重启 |
| `-sA` / `-D` / `-f` / `--data-length` | 属规避检测手段 | 违约、被认定"规避安全措施" |
| `-S` 伪造源地址 | 冒用第三方地址 | 违法，且给无关方带来麻烦 |
| `http-enum` 等目录枚举 | 请求量可达数千 | WAF 封禁、日志爆炸 |

> [!WARNING]
> 本书正文对 `brute` / `dos` / `exploit` / `intrusive` / `fuzzer` / `vuln` 六类脚本**只说明用途与风险，不提供任何组合流程**。
>
> 这不是保守，是因为这六类脚本在真实环境中的失败模式是**不可逆**的：账号被锁、服务崩溃、数据被改。而这些后果通常由**授权方**承担，不是你。

## 10.4 法律框架（概要）

> 以下仅为**方向性说明**，不构成法律意见。具体条文、适用范围与量刑，请以官方文本与专业律师意见为准；涉及跨境目标时尤其需要本地法律意见。

### 10.4.1 中国

| 法规 | 相关方向 |
| --- | --- |
| 《中华人民共和国网络安全法》 | 网络运营者安全义务；未经授权侵入他人网络、干扰正常功能属违法 |
| 《中华人民共和国刑法》第二百八十五条 | 非法侵入计算机信息系统罪；非法获取计算机信息系统数据、非法控制计算机信息系统罪 |
| 《中华人民共和国刑法》第二百八十六条 | 破坏计算机信息系统罪（含"干扰"导致不能正常运行） |
| 《中华人民共和国数据安全法》 | 扫描过程中获取的数据属"数据"，处理需合法依据 |
| 《中华人民共和国个人信息保护法》 | 若 banner/证书/目录中夹带个人信息，处理受该法约束 |

**要点**：刑法 285/286 的构成不以"造成实际损失"为唯一前提，"侵入""干扰"本身即可入罪。实务中"我只扫了端口没做别的"通常**不构成有效抗辩**。

### 10.4.2 美国

- **CFAA（Computer Fraud and Abuse Act, 18 U.S.C. § 1030）**：未经授权访问受保护计算机。判例对"授权边界"的解释存在分歧，但**未经许可的漏洞扫描被起诉的案例真实存在**。
- 州层面另有各自法律（如加州刑法 § 502）。

### 10.4.3 欧盟 / 英国

- **Computer Misuse Act 1990（英国）**：未经授权访问、未经授权修改，均为独立罪名。
- 欧盟各国多在网络犯罪公约（Budapest Convention）框架下立法，条款结构类似。

### 10.4.4 一个实用的判断法

```text
如果目标所有者明天在法庭上拿出你今天的扫描日志，
你能出示什么证明他同意过？
    └─ 一份写明范围、时间、手段、签字的授权书 → 可以辩
    └─ 什么都没有，或只有聊天记录里一句"你试试" → 很难辩
```

## 10.5 授权范围内的行为边界

即使有授权，以下行为仍可能越界：

| 行为 | 为什么危险 |
| --- | --- |
| 从目标扫到**相邻 IP**（网段写宽了） | 相邻 IP 可能是别人的资产 |
| 扫描**第三方托管**的子域（CDN、SaaS） | 资产所有者不一定有权授权那部分 |
| 用**别人的 IP 做诱饵**（`-D`） | 牵连无关第三方 |
| 把扫到的**凭证、个人信息**存到自己的笔记/网盘 | 数据合规问题，可能构成非法获取数据 |
| 把结果发到**公开群/社交平台** | 泄漏 + 未授权披露 |
| 发现漏洞后**自行验证到"能利用"** | 从"检测"越界到"利用" |

## 10.6 扫描对业务的实际影响

技术人容易低估这个。以下是真实发生过的后果类型：

| 影响 | 触发条件 |
| --- | --- |
| 老式打印机/嵌入式设备**死机** | `-O` 或 `-sV` 的非常规包 |
| WAF 把整个 IP 段拉黑 | 目录枚举、高频扫描 |
| 运维账号被锁 | `brute` 类脚本撞上 AD 锁定策略 |
| 日志/存储费用暴涨 | `-sT` + 大范围扫描产生海量连接日志 |
| 值班被半夜叫起来 | 任何触发 IDS 高危告警的扫描 |
| 云厂商安全组自动封禁 | 高频 SYN |

**这也是为什么"先约定速率、先报备出口 IP"不是形式主义。**

## 10.7 事故处置

万一扫描过程中把服务搞挂了，或者被对方安全团队找上门：

```text
① 立即停止所有扫描。
② 保存现场：命令、时间、输出文件、你自己的出口 IP。不要删日志。
③ 立刻通知授权联系人（电话，不是邮件）。说明：做了什么、什么时间、现在什么状态。
④ 配合恢复。不要自己去"试着修"，你不是运维。
⑤ 事后写清时间线与根因，纳入报告。隐瞒比事故本身更严重。
```

**绝对不要做的事**：删日志、清历史、换个 IP 继续扫、假装没发生。

## 10.8 本书的自我约束

作为一份教学材料，本仓库遵守以下规则，并请你一起维护：

| 规则 | 具体做法 |
| --- | --- |
| 不提供未授权攻击流程 | 所有涉及 `brute`/`dos`/`exploit` 的内容只讲用途与风险，不写组合步骤 |
| 不提供可直接利用的 PoC | 涉及漏洞只写"如何判断存在性线索"，不写利用 |
| 示例地址一律脱敏 | 只用 RFC 5737 / RFC 3849 文档段与私网段 |
| 输出样本必须真实 | 没有真实输出就写【待补充示例输出】，不编造 |
| 高风险内容强制标注 | `> [!WARNING]` 块，写明可能后果 |
| 明确"在哪里停下" | 每个涉及深入验证的段落，都给出"停"的边界 |

## 10.9 学习者自我检查

开扫前，逐条回答。**任何一条答不上来，就不要扫。**

- [ ] 这个目标的**所有者**是谁？我凭什么认为他同意了？
- [ ] 授权是**书面**的吗？里面有 IP/域名/端口/时间窗吗？
- [ ] 我的命令**会不会超出**那个范围（网段写宽了？CDN？第三方托管？）？
- [ ] 我要用的技术手段（脚本类别、全端口、UDP、规避参数）在授权里写明了吗？
- [ ] 如果这台机器挂了，我知道该打给谁吗？
- [ ] 我扫到的数据要存在哪？会不会带个人信息？

## 本章初学者检查清单

- [ ] 能说出"公网可达"与"允许扫描"的区别
- [ ] 知道一份合格授权必须包含的六个要素
