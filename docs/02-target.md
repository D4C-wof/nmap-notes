# 02 · 目标怎么指定

> **本章目标**：把"我要扫谁"这件事写对。目标写错，后面所有参数都白费；目标写宽了，可能扫到不该扫的机器。

## 2.1 一句话原则

Nmap 的目标参数只解决四件事：**单个目标、多个目标、一段目标、从文件读目标**。此外还有两个补充动作：**排除**和**限定协议版本**。

```text
nmap [目标写法] [排除] [协议族]
```

多个目标之间用**空格或逗号**分隔，两种写法等价：

```bash
nmap 192.0.2.10 192.0.2.11
nmap 192.0.2.10,192.0.2.11
```

## 2.2 IP 地址与域名

### 命令

```bash
nmap 192.0.2.10
nmap example.com
```

### 适用场景

已知目标的确切地址，做单点摸底。

### 示例

```bash
# 单个 IP
nmap -F 192.0.2.10

# 域名（Nmap 会先做 DNS 解析）
nmap -F example.com
```

### 示例输出

【待补充示例输出】建议补充：同一目标分别用 IP 与域名扫描时，输出首行差异的对照——域名扫描会多一行 `Nmap scan report for example.com (192.0.2.10)`，
用于说明"域名会被解析成 IP，报告里两者都显示"。

### 结果判读

用域名扫描时，报告标题形如：

```text
Nmap scan report for <域名> (<解析出的IP>)
```

如果括号里的 IP 和你在 DNS 里查到的不一致，说明中间有 CDN、负载均衡或 DNS 污染。**这时你扫的是 CDN 边缘节点，不是源站**——这是初学者最容易得出的错误结论之一。

### 注意事项

- 一个域名可能解析出多个 A 记录，Nmap **默认只扫第一个**。要全扫所有解析结果，用 `--resolve-all`
  （官方手册原话："To make Nmap scan all the resolved addresses instead of only the first one, use the `--resolve-all` option"），
  或自己解析出 IP 列表后传给 Nmap。
- 域名解析默认走本机 DNS。想指定 DNS 服务器，见 [2.7](#27-dns-相关参数)。
- 扫域名前先 `nslookup <域名>` / `dig <域名>` 看一眼解析结果，能省掉大量误判。

### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 解析出的是 CDN 地址 | 先确认授权范围是否覆盖该 CDN；不要在未授权情况下继续 |
| 解析出多个 IP | 逐个确认是否都在 scope 内，再分别扫 |
| 解析失败 | 进 [09 章 DNS 解析失败](09-troubleshooting.md#93-dns-解析失败) |

## 2.3 网段（CIDR）

### 命令

```bash
nmap -sn <目标网段>
```

### 适用场景

拿到一段内网地址或一个云上 VPC 段，想知道里面有多少台机器活着。

### 示例

```bash
nmap -sn 192.0.2.0/24
```

### 示例输出

【待补充示例输出】建议补充：一个 8 台主机在线的 `/24` 网段的 `-sn` 输出，用于展示"每台主机两行、无端口表"的形态，以及结尾的 `Nmap done:
256 IP addresses (8 hosts up) scanned in ...`。

### 结果判读

- 一个 `/24` = 256 个地址（含网络地址与广播地址），实际可分配给主机的是 254 个。
- 结尾统计里的 `(256 IP addresses ... 8 hosts up)` 是**发包数**与**存活数**，不是"扫了 254 台"。
- 没有出现的地址就是没响应，不代表不存在——可能被防火墙静默丢弃。

### 注意事项

| 网段写法 | 地址数 | 现实耗时（`-sn`，局域网） |
| --- | --- | --- |
| `/24` | 256 | 秒级 |
| `/16` | 65536 | 分钟级，且容易触发告警 |
| `/8` | 16777216 | **不要这么做**，这已经是大规模扫描行为 |

- **合规红线**：扫一个不属于你的 `/16`，在很多司法辖区已经构成"非法侵入计算机信息系统"的客观行为，不管你有没有做进一步操作。
- 网段扫描前先确认掩码。`192.0.2.10/24` 和 `192.0.2.10/28` 差了 16 倍。

### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 存活主机很多 | 先挑关键目标做 `-F`，不要对全网段跑全端口 |
| 一台都没扫到 | 大概率 ICMP 被拦，换 `-PS` 或 `-Pn`，见 [03 章](03-host-discovery.md) |
| 需要排除网关、打印机等设备 | 用 `--exclude`，见 [2.5](#25-排除目标) |

## 2.4 从文件读目标（`-iL`）

### 命令

```bash
nmap -iL <文件名>
```

### 适用场景

目标有几十上百个，或者是上一个工具（子域枚举、资产清单）的输出，手工敲不现实。

### 示例

准备 `targets.txt`，一行一个目标，支持 IP、域名、网段、范围混写：

```text
# 这是注释行，Nmap 会忽略
192.0.2.10
192.0.2.0/28
example.com
198.51.100.20-30
```

执行：

```bash
nmap -sn -iL targets.txt
```

### 示例输出

【待补充示例输出】建议补充：一个含 4 行（IP / 网段 / 域名 / 范围）的 `targets.txt` 对应的 `-sn -iL` 输出，用于说明"文件里每种写法都被展开"以及注释行被跳过。

### 结果判读

- 输出顺序**不保证**与文件顺序一致（Nmap 会并发）。
- 想保留顺序、逐个扫，用 `-iL <文件名> -sL` 先只列目标不扫描来验证读入是否正确。

> `-sL`（列表扫描）只解析并打印目标，不发探测包。**这是校验 `-iL` 是否读对的最安全手段**，强烈建议每次大批量扫描前先跑一次。

### 注意事项

- 文件编码用 UTF-8，行尾用 LF 或 CRLF 都能读，但从 Windows 记事本复制来的文件常带 BOM，可能导致第一个目标解析失败——用编辑器另存为"UTF-8 无 BOM"。
- 空行会被忽略，`#` 开头的注释行会被忽略。
- 文件里写了一个巨大的网段（如 `/8`），Nmap 不会警告你，会直接开始扫。**读文件前先 `cat` 一遍。**

### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 不确定读入是否正确 | 先 `nmap -sL -iL <文件名>` |
| 目标太多跑不完 | 分批：按网段拆文件，或用 `--exclude` 剔除已知设备 |
| 想边扫边输出 | 加 `-oA <文件名>`，见 [07 章](07-speed-evasion-output.md) |

## 2.5 排除目标

### 命令

```bash
nmap <目标网段> --exclude <目标IP>
```

### 适用场景

扫一个网段，但要跳过网关、核心交换机、生产数据库、老板的笔记本这类**不能碰**的设备。

### 示例

```bash
# 排除单台
nmap -sn 192.0.2.0/24 --exclude 192.0.2.1

# 排除多台（逗号分隔）
nmap -sn 192.0.2.0/24 --exclude 192.0.2.1,192.0.2.254

# 排除一段
nmap -sn 192.0.2.0/24 --exclude 192.0.2.100-110

# 排除整个网段
nmap -sn 192.0.2.0/24 --exclude 192.0.2.128/25
```

### 示例输出

【待补充示例输出】建议补充：对 `/24` 加 `--exclude 192.0.2.1` 前后的两次 `-sn` 输出对比，证明被排除地址不再出现在 `Nmap scan report for` 行中。

### 结果判读

被排除的地址**完全不会发包**，也不会出现在结果里。判据是：输出中检索不到该地址的任何行。如果还能看到，说明 `--exclude` 写错了位置（必须在目标之后，不能放在 `nmap` 与目标之间）。

### 注意事项

- `--exclude` 只接受**与目标同族**的地址。扫 IPv6 时要排除 IPv6 地址。
- 排除列表也可以用文件：`--excludefile <文件名>`，格式与 `-iL` 相同。
- 排除是"防手滑"，**不是"防法律风险"**。真正决定能不能扫的是授权范围，不是这一行参数。

### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 排除的设备很多且固定 | 写进 `exclude.txt`，用 `--excludefile`，并纳入版本管理 |
| 排除后仍有告警 | 检查是否有其他扫描器/同事在同一时间段操作 |

## 2.6 IPv6 目标（`-6`）

### 命令

```bash
nmap -6 <IPv6地址>
```

### 适用场景

目标网络启用了 IPv6，或你要验证"IPv4 端口全关但 IPv6 全开"这类常见配置错误。

### 示例

```bash
nmap -6 -sn 2001:db8::/64
```

### 示例输出

【待补充示例输出】建议补充：`2001:db8::/64` 网段 `-sn` 的输出片段，展示 IPv6 地址在报告中的书写形式（全展开 vs 压缩），以及 `Nmap done:
... (0 hosts up)` 时如何判断是"没主机"还是"不支持"。

### 结果判读

- `2001:db8::/64` 是 RFC 3849 保留给文档使用的 IPv6 段，**永远不会路由到真实主机**。
- IPv6 没有 ARP，局域网内主机发现靠 ICMPv6 邻居发现，`-PR` 在纯 IPv6 环境下不适用。

### 注意事项

| 限制 | 说明 |
| --- | --- |
| 必须显式加 `-6` | 不加则所有目标按 IPv4 解析 |
| 部分 NSE 脚本不支持 IPv6 | 跑脚本前看 `--script-help` 的说明 |
| 操作系统识别对 IPv6 支持有限 | `-O` 在 IPv6 上常无结果，属正常现象 |
| 网段写法 | IPv6 用 `/64` 这类前缀，不能用 `1-20` 范围写法 |

### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| IPv4 扫完想对比 IPv6 | 同一份端口列表分别跑 `-4`/`-6`，用 `diff` 比对 |
| 目标是双栈 | 两边都要扫，只扫一边会漏掉一半攻击面 |

## 2.7 DNS 相关参数

### 2.7.1 禁用 / 强制解析

| 参数 | 作用 | 什么时候用 |
| --- | --- | --- |
| `-n` | 不做反向 DNS 解析 | 大规模扫描时省时间。**这是提速最划算的一行参数** |
| `-R` | 强制对**所有**目标做反向解析 | 想从 PTR 记录里找主机名线索时 |

**为什么 `-n` 能明显提速**：默认情况下 Nmap 会对每个存活 IP 做一次 PTR 查询，而很多内网 DNS 服务器响应很慢或直接超时。一个 /24 网段可能因此多花几十秒。

#### 命令

```bash
nmap -n -F <目标IP>
```

#### 适用场景

目标数量多、DNS 服务器慢、或你根本不关心主机名。

#### 示例

```bash
nmap -n -sn 192.0.2.0/24
```

#### 示例输出

【待补充示例输出】建议补充：同一 `/24` 网段在 `-sn` 与 `-sn -n` 下的输出对比，重点展示"报告行从 `Nmap scan report for
host-a.example.com (192.0.2.10)` 变成 `Nmap scan report for 192.0.2.10`"，以及结尾耗时的差异（需注明测试环境，否则耗时数字无意义）。

#### 结果判读

加 `-n` 后，报告行只剩 IP。**不会**因此少扫端口，只是少了一次查询。

#### 注意事项

- `-n` 与 `-R` 互斥，别同时给。
- 反向解析成功不代表这个主机名可信——PTR 记录由 IP 所有者自己填，可以是任意值。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 想从主机名判断设备角色 | 去掉 `-n` 重扫目标子集即可，不必重扫全网段 |
| 解析很慢但想要主机名 | 用 `-n` 先扫，事后对存活 IP 单独批量 `dig -x` |

### 2.7.2 指定 DNS 服务器

#### 命令

```bash
nmap --dns-servers <DNS服务器IP> <域名>
```

#### 适用场景

本机 DNS 解析不到目标（内网域名、测试环境域名），或想用特定的 DNS 视角验证解析结果。

#### 示例

```bash
nmap -F --dns-servers 192.0.2.53 example.com
```

#### 示例输出

【待补充示例输出】建议补充：用 `--dns-servers` 指向一个自建 DNS（如本地 dnsmasq）后的成功输出，以及指向一个不可达 DNS 时的失败输出，用于对比"解析成功"与"解析失败"在报告开头的差异。

#### 结果判读

- 成功：报告行显示 `Nmap scan report for <域名> (<IP>)`。
- 失败：会出现 `Failed to resolve "<域名>"`，该目标被跳过，**扫描继续但不含它**。

#### 注意事项

- **`--dns-servers` 只影响 Nmap 自己的解析**，不会改系统 DNS。
- 原文提到"常见 DNS 域名服务器可以在网上搜索"——**不建议**随手用公共 DNS 去解析内网域名，那必然失败，而且会把内网域名泄漏给第三方。内网目标应该用内网 DNS。
- 传输安全：传统 DNS 查询是明文的。用第三方 DNS 解析敏感域名，等于把你的目标清单广播出去。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 解析失败 | 先 `dig @<DNS服务器IP> <域名>` 验证该 DNS 是否知道这个名字 |
| 解析到多个 IP | 逐个确认是否在授权范围内 |
| 内网域名 | 用企业内网 DNS，不要用 8.8.8.8 之类 |

## 2.8 目标写法速查

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `<IP>` | 单个地址 | `192.0.2.10` |
| `<域名>` | 先解析再扫描 | `example.com` |
| `<网段>` | CIDR | `192.0.2.0/24` |
| `<起始IP>-<结束>` | 末段闭区间 | `192.0.2.10-20` |
| `<网段>,<IP>` | 多目标混合 | `192.0.2.0/28,198.51.100.5` |
| `-iL <文件名>` | 从文件读 | `-iL targets.txt` |
| `--exclude <IP>` | 排除 | `--exclude 192.0.2.1` |
| `--excludefile <文件名>` | 从文件排除 | `--excludefile exclude.txt` |
| `-6` | 按 IPv6 处理 | `-6 2001:db8::1` |
| `-sL` | 只列目标不扫描 | `-sL -iL targets.txt` |

## 本章修改说明

1. 原文目标参数是 8 条并列词条，无优先级。本章按"单点 → 批量 → 排除 → 协议族 → DNS"重排，形成可执行顺序。
2. 原文 `192.168.122.0/24`、`192.168.1.1-20`、`192.168.44.25` 等示例地址统一替换为 RFC 5737 文档地址段，避免读者照抄扫到真实设备。
3. 原文未提 `-sL`（列表扫描）与 `-iL` 的配合，补充"先验证读入再扫描"这一步，这是批量扫描最实用的安全阀。
4. 原文 `--dns-servers` 的说明含"网上搜索 DNS 服务器"的建议，本章改为强调内网用内网 DNS，并补充明文查询的数据外传风险。
5. 原文注释"`-iL<文件名>`"缺空格，统一为 `-iL <文件名>`，与 `nmap --help` 写法一致。
