# 06 · NSE 脚本引擎

> **本章目标**：会用 NSE 拿信息，会读脚本输出，**并且知道哪些脚本不该碰**。
>
> ⚠️ 本章是全书中**风险最高**的一章。请先读 [6.6 风险分级](#66-脚本类别与风险分级) 再动手。

## 6.1 NSE 是什么

NSE（Nmap Scripting Engine）让 Nmap 从"端口扫描器"变成"可编排的信息收集平台"。脚本用 Lua 写，内置几百个，覆盖从"读一个 HTTP 标题"到"检测某个漏洞是否存在"的各种任务。

```text
Nmap 主体  ──调用──▶  NSE 引擎  ──执行──▶  Lua 脚本  ──发包──▶  目标
                                    │
                                    └──▶ 结构化输出（表格/键值/列表）
```

**能力边界**：

| NSE 能做的 | NSE 不该被当成 |
| --- | --- |
| 识别服务细节（HTTP 标题、TLS 证书、SSH 主机密钥） | 漏洞扫描器（它没有 PoC 库，也没有误报控制） |
| 枚举共享、用户、目录、SNMP 对象 | 渗透框架（它不维持会话、不做后渗透） |
| 检查某个已知漏洞的**存在性**（部分脚本） | 授权凭证（跑脚本不等于有授权） |
| 与目标服务做协议级对话 | 稳妥的生产环境工具（很多脚本会改变目标状态） |

## 6.2 三类调用方式

### 6.2.1 `-sC`：运行默认脚本集

#### 命令

```bash
nmap -sC -p <端口列表> <目标IP>
```

#### 适用场景

"我想在这个端口上多知道一点，但不想自己挑脚本"。

#### 示例

```bash
nmap -sV -sC -p 22,80,443 192.0.2.10
```

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：对一台跑着 Web 服务的本地靶机执行 `-sV -sC`，输出中需包含至少一条 `|_http-title:`、一条 `| ssl-cert:` 多行脚本块，
用于展示"单行 `|_`"与"多行 `|`"两种输出形态的差别。

#### 结果判读

脚本输出插在端口表**下方**，紧跟在对应端口之后。两种行首标记必须分清：

| 标记 | 含义 |
| --- | --- |
| `\|_` | 脚本输出的**最后一行**（`_` 表示结束） |
| `\|` | 脚本输出的**中间行**（后面还有） |
| `\|_http-title: <标题>` | 单行结果：脚本 `http-title` 的输出 |

例：

```text
443/tcp open  ssl/http <产品名> <版本>
| ssl-cert: Subject: commonName=<域名>
| Subject Alternative Name: DNS:<域名>, DNS:<域名>
| Not valid before: <日期>
|_Not valid after:  <日期>
|_http-title: <页面标题>
```

**这是全章最实用的技能**：能一眼看出"哪些行属于同一个脚本"。

#### 注意事项

- `-sC` 等价于 `--script=default`，与 `-A` 中的脚本部分相同。
- **`default` 类别不等于"无害"**：`default` 的筛选标准是"覆盖面广 + 影响度低"，不是"零影响"。它仍会向目标发大量请求。
- `-sC` 会明显拉长扫描时间，且在有 WAF 的环境里极易触发拦截。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 看到 `http-title` 是登录页 | 想看目录 → `--script http-enum`（见 6.4） |
| 看到 `ssl-cert` 的 CN 与访问域名不符 | 记录为配置问题线索，不要就此断言"证书伪造" |
| 脚本报 `ERROR` | 通常是脚本不支持该服务版本，不是目标有问题 |

### 6.2.2 `--script=<脚本名>`

#### 命令

```bash
nmap -p <端口> --script <脚本名> <目标IP>
```

#### 适用场景

已经知道要查什么，只跑那一个脚本。**这是最推荐的用法**——比 `-sC` 精准、噪音小。

#### 示例

```bash
# 只取 HTTP 标题
nmap -p 80,443 --script http-title 192.0.2.10

# 多个脚本用逗号分隔
nmap -p 80 --script http-title,http-headers 192.0.2.10
```

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：`--script http-title` 对单个 Web 端口的输出，用于展示"只多出一行 `|_http-title:`，其余与普通扫描一致"。

#### 结果判读

只影响**匹配该脚本适用端口/协议**的端口。脚本对不适用的端口不会输出任何内容——**"没有输出"不等于"没有发现"**，可能只是脚本没跑（端口不对、协议不对）。

#### 注意事项

- 脚本名写错不会报错，只会静默不执行。用 `--script-help <脚本名>` 确认存在。
- 一个脚本可能只在特定端口上有效（`http-*` 只跑在识别为 http 的端口上）。
- 脚本是**主动发包**的，`http-*` 类会在目标 Web 日志里留下记录。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 脚本无输出 | 先 `--script-help <脚本名>` 看适用条件；再确认端口被识别为正确服务（`-sV`） |
| 输出内容很多 | 用 `-oN` 存下来读，别在终端里翻 |

### 6.2.3 `--script=<类别>`

#### 命令

```bash
nmap -p <端口列表> --script <类别> <目标IP>
```

#### 适用场景

想跑"一整类"脚本，比如所有 `safe` 的、所有 `discovery` 的。

#### 示例

```bash
# 只跑安全类（相对最温和的一档）
nmap -sV -p 80,443 --script "safe" 192.0.2.10

# 组合：default 里排除 intrusive（表达式用法）
nmap -sV -p 80,443 --script "default and not intrusive" 192.0.2.10
```

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：`--script safe` 与 `--script default` 在同一目标上的输出行数对比，用于说明"类别越大，输出越杂"。

#### 结果判读

类别是**标签**，一个脚本可以同时属于多个类别（如 `http-title` 同时属于 `default`、`discovery`、`safe`）。所以：

```text
safe 的数量 < default 的数量 < 全部脚本的数量
```

脚本支持的表达式（来自官方文档语义）：

| 写法 | 含义 |
| --- | --- |
| `a,b` | a 或 b |
| `a and b` | 交集 |
| `a or b` | 并集 |
| `not a` | 排除 a |
| `a and not b` | a 中排除 b |

#### 注意事项

> [!WARNING]
> **不要用 `--script all`。** 它会跑全部脚本，其中包含 `dos`、`exploit`、`brute`、`intrusive` 类。对任何非靶场目标执行，都可能造成服务中断或产生大量失败登录。

- 类别名不区分大小写，但**拼错就静默不跑**。
- 表达式里含空格时**必须加引号**，否则被 shell 拆成多个参数。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 想更精准 | 回到 `--script=<脚本名>` 逐个点名 |
| 想排除危险类 | `--script "default and not (brute or dos or exploit or intrusive)"` |

## 6.3 传参与查看帮助

### 6.3.1 `--script-args`

#### 命令

```bash
nmap -p <端口> --script <脚本名> --script-args <键>=<值> <目标IP>
```

#### 适用场景

脚本有可配置项：要访问哪个路径、用哪个用户名、超时多少、输出多详细。

#### 示例

```bash
# 指定要请求的路径
nmap -p 80 --script http-title --script-args http-title.url=/login 192.0.2.10

# 多个参数用逗号分隔
nmap -p 80 --script http-headers --script-args http.useragent="Mozilla/5.0",http.max-cache-size=100000 192.0.2.10
```

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：同一脚本在带 `--script-args` 与不带时输出的差异（例如 `http-title.url` 指向 `/login` 后标题变成登录页标题），用于说明"参数真的生效了"。

#### 结果判读

- 参数生效时，输出内容会随参数变化；
- 参数名写错**不会报错**，脚本按默认值跑——这是最常见的"参数没起作用"原因；
- 复杂参数（嵌套表、数组）的写法每个脚本都不一样：先用 `nmap --script-help <脚本名>` 看该脚本自己的参数说明，
  再照着写，不要凭 `--script-args` 的通用文档猜结构。

#### 注意事项

| 坑 | 说明 |
| --- | --- |
| 引号 | 参数值含空格或逗号时整体加引号：`--script-args "key=value with space"` |
| 参数过多 | 用 `--script-args-file <文件名>` 从文件读，避免命令行过长 |
| 覆盖关系 | `--script-args` 与脚本默认值合并，不是替换 |
| 安全 | **不要把密码写在命令行里**——会进 shell 历史、进程列表、CI 日志 |

> [!WARNING]
> 涉及凭证的参数（`*-brute` 类的 `userdb` / `passdb`、`http-brute` 的 `http-brute.path`）属于**高风险用法**。
> 本书不提供任何"默认字典 + 批量爆破"的组合示例。相关测试必须在隔离靶场、并取得明确书面授权后进行。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 参数没生效 | `--script-help <脚本名>` 核对参数名拼写 |
| 参数很多且反复用 | 写进 `args.txt`，用 `--script-args-file args.txt` |

### 6.3.2 `--script-help`

#### 命令

```bash
nmap --script-help <脚本名>
nmap --script-help "<表达式>"
```

#### 适用场景

**跑任何不熟悉的脚本之前，先跑这个。** 它会打印脚本的作者、类别标签、描述和可用参数。

#### 示例

```bash
nmap --script-help http-title
nmap --script-help "smb-*"
nmap --script-help "default and safe"
```

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：`nmap --script-help http-title` 的实际输出（含 `Categories:` 行与 `Arguments:` 行），这是本章最应该给真实输出的一处，因为它不含目标信息、无脱敏负担。

#### 结果判读

重点看三行：

| 行 | 为什么重要 |
| --- | --- |
| `Categories:` | 判断风险等级的第一依据（是否含 `intrusive` / `dos` / `brute` / `exploit`） |
| `Arguments:` | 有哪些 `--script-args` 可用，以及默认值 |
| 描述段落 | 脚本到底会做什么、会不会改变目标状态 |

#### 注意事项

- `--script-help` **不需要目标**，纯本地查库，随便跑。
- 支持通配符：`smb-*` 会列出所有 SMB 相关脚本。
- 它显示的是脚本自带的元数据，**不是官方担保**——脚本作者写的 `safe` 标签也可能是错的。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| `Categories:` 含 `intrusive`/`dos`/`brute`/`exploit` | 停下，确认授权与环境后再考虑 |
| `Arguments:` 里有你没见过的键 | 先不加参数跑一次默认行为，再逐步加 |

### 6.3.3 其他有用的脚本参数

| 参数 | 作用 | 什么时候用 |
| --- | --- | --- |
| `--script-trace` | 打印脚本收发的每个包 | 脚本输出为空，想确认它到底发没发包 |
| `--script-timeout <时间>` | 单脚本超时 | 某个脚本卡住不返回 |
| `--script-updatedb` | 更新脚本数据库 | 手动往 `scripts/` 放了脚本后 |
| `--script-args-file <文件名>` | 从文件读参数 | 参数多或含敏感值 |

## 6.4 常用脚本速查（低风险优先）

下面只列**信息收集类**脚本。它们仍会发包、留日志，但设计目的不是改变目标状态。

| 脚本 | 适用端口 | 输出什么 | 风险 |
| --- | --- | --- | --- |
| `http-title` | 80/443/8080… | 页面 `<title>` | 低 |
| `http-headers` | HTTP | 响应头 | 低 |
| `http-enum` | HTTP | 常见路径/后台目录是否存在 | **中**：会发大量请求，易触发 WAF |
| `ssl-cert` | TLS | 证书主题、SAN、有效期 | 低 |
| `ssl-enum-ciphers` | TLS | 支持的加密套件与强度评级 | 中 |
| `ssh-hostkey` | 22 | SSH 主机密钥指纹 | 低 |
| `ssh-auth-methods` | 22 | 允许的认证方式 | 低 |
| `smb-os-discovery` | 445 | 目标系统/域/主机名 | 中 |
| `smb-enum-shares` | 445 | 共享列表与权限 | 中 |
| `dns-zone-transfer` | 53 | 尝试 AXFR 区域传送 | **中高**：属于对 DNS 的攻击性查询 |
| `snmp-info` | 161/udp | 设备型号、系统信息 | 中 |
| `ftp-anon` | 21 | 是否允许匿名登录 | 中 |

> 表中"风险"指**可能造成的影响与告警概率**，不是法律风险。法律风险由授权决定，与脚本无关。

### 6.4.1 一个完整的低风险示例

#### 命令

```bash
nmap -sV -p 80,443 --script "http-title,http-headers,ssl-cert" 192.0.2.10
```

#### 适用场景

Web 资产初筛：想知道站点标题、服务器类型、证书信息。

#### 示例

见上。

#### 示例输出

【自测留白】在你自己的环境里跑一次，把真实输出贴到下面。要记录的内容：对本地靶场（如 DVWA/Juice Shop）执行该命令的完整脚本段，要求同时出现单行 `|_` 与多行 `|` 两种形态。

#### 结果判读

| 输出 | 可推断 | 不可推断 |
| --- | --- | --- |
| `http-title: <标题>` | 站点用途（登录页/管理后台/默认页） | 是否存在漏洞 |
| `Server: <产品>/<版本>` | 中间件类型与版本 | 版本一定存在已知漏洞（需查证） |
| 证书 CN ≠ 访问域名 | 配置问题或多域名部署 | 一定是"证书伪造" |
| 无 `ssl-cert` 输出 | 该端口不是 TLS，或握手失败 | 一定没有证书 |

#### 注意事项

- `http-enum` 虽然常用，但它是**目录爆破**：会发几百上千个请求。对生产站点使用前必须确认授权，且建议限速。
- **不要在本书流程里把 `http-enum` 的"发现 `/admin/`"直接等同于"存在未授权访问"**。发现路径只是线索，验证需要另行授权。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 发现后台路径 | **停止自动探测**。记录线索，交人工与授权方确认 |
| 证书里有多个域名 | 记录为资产关联线索（可能还有同证书的其他站点） |
| 服务版本明确 | 查官方漏洞库核对影响范围（注意：查证 ≠ 可验证） |

## 6.5 `-sC` 与 `--script` 的关系

| 命令 | 等价于 | 说明 |
| --- | --- | --- |
| `-sC` | `--script=default` | 默认脚本集 |
| `-A` | `-sV -O -sC --traceroute` | 含默认脚本集 |
| `--script default` | 同 `-sC` | 两种写法等价 |
| `--script safe` | 所有标 `safe` 的脚本 | 范围比 `default` 大 |

**注意**：`-sC` 与 `--script` 同时出现时，`--script` 会**覆盖** `-sC`，不是叠加。想要两者都有，写全：`--script "default,http-title"`。

## 6.6 脚本类别与风险分级

Nmap 官方把脚本按用途打标签。下表按**风险从低到高**重排，并给出本书的使用建议。

| 类别 | 用途 | 会改变目标状态吗 | 风险 | 本书建议 |
| --- | --- | --- | --- | --- |
| `safe` | 设计上不破坏目标 | 否 | 低 | 可用于授权目标 |
| `discovery` | 信息收集主力：SMB 枚举、SNMP 查询、目录枚举 | 可能有副作用 | 中 | 逐个点名使用，不要整类跑 |
| `default` | 默认集，`-sC`/`-A` 自动加载 | 一般不会 | 中 | 常规可用，注意日志量 |
| `version` | 增强 `-sV` 版本识别 | 否 | 低 | 可放心用 |
| `auth` | 鉴权机制探测、弱口令检测 | **可能** | 中高 | 只做机制探测，不做口令尝试 |
| `broadcast` | 局域网广播发现（DHCP/DNS/SQL Server） | 可能 | 中 | 仅限自己网段 |
| `external` | 依赖第三方数据源（如 WHOIS） | 否，但**数据外传** | 中 | 注意目标信息泄漏给第三方 |
| `malware` | 检测后门/感染迹象 | 可能 | 中 | 仅授权环境 |
| `vuln` | 漏洞**存在性**检测 | **可能**（部分脚本会触发崩溃） | **高** | 见下方警告 |
| `intrusive` | 侵入性脚本，易触发 IDS/IPS | **是** | **高** | 仅隔离靶场 |
| `fuzzer` | 模糊测试，发异常包 | **可能致崩溃** | **高** | 仅隔离靶场 |
| `brute` | 暴力破解口令（SSH/MySQL/SNMP…） | **是**（锁定账号、日志爆炸） | **高** | 仅隔离靶场，需专门授权 |
| `dos` | 拒绝服务测试 | **是** | **极高** | 仅隔离靶场，需专门授权 |
| `exploit` | 利用漏洞入侵 | **是** | **极高** | 仅隔离靶场，需专门授权 |

> [!WARNING]
> **`brute` / `dos` / `exploit` / `fuzzer` / `intrusive` / `vuln` 六类脚本，本书只说明用途与风险，不提供任何组合攻击流程。**
>
> 它们可能造成的真实后果：
>
> - **账号锁定**：企业的 AD/SSH 通常有失败次数策略，几次错误就锁定运维账号，导致业务中断；
> - **日志爆炸**：一次 `brute` 可能产生数万条失败登录，把 SIEM 账单和值班同学一起点燃；
> - **服务崩溃**：`fuzzer` 与部分 `vuln` 脚本会让老服务直接挂掉（尤其嵌入式设备、老旧打印机）；
> - **不可逆状态变更**：`exploit` 类脚本一旦成功，目标可能被写入文件、创建账号、重启服务。
>
> 在客户环境中执行上述脚本，通常需要**单独的、写明脚本名的书面授权**，普通"允许扫描"的授权不覆盖它们。

### 6.6.1 怎么判断一个脚本能不能跑

```text
① 这个脚本属于哪些类别？            → --script-help <脚本名> 看 Categories
② 它有没有 dos/brute/exploit/intrusive/fuzzer 标签？
      有 → 停。除非这是你的靶场且你明确要测这个。
      没有 → 继续
③ 它会不会发大量请求？              → 描述里有没有 "enumerate" / "brute" / "fuzz"
④ 目标是不是生产环境？
      是 → 先用 --script-timeout 和低速率跑单个脚本，观察
⑤ 跑完检查：目标服务还正常吗？日志有没有异常？
```

## 6.7 脚本输出读不懂怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 完全没有脚本输出 | 端口没被识别为对应服务 | 先 `-sV` 确认协议 |
| 有 `ERROR: Script execution failed` | 脚本与目标版本不兼容 | 换脚本或跳过，不是目标的问题 |
| 输出是 Lua 表结构 | 脚本返回了未格式化的结构 | 属正常，按字段名读 |
| 输出被截断 | 内容过长 | `-oN` 存文件 |
| 同一端口出现多个脚本输出 | 多个脚本都匹配该端口 | 按 `\|` 缩进层级分组阅读 |
