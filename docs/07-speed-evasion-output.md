# 07 · 速度、规避与输出

> **本章目标**：让扫描跑得完、不把自己搞黑名单、结果能留下来复核。
>
> 三块内容放在一章，因为它们共享同一个底层矛盾：**速度 ↔ 隐蔽 ↔ 准确**，三角形的三个角，最多同时占两个。

## 7.1 速度控制

### 7.1.1 `-T0` ~ `-T5`：定时模板

#### 命令

```bash
nmap -T<0-5> <目标IP>
```

#### 适用场景

不想逐个调参时，用现成的预设组合。

#### 示例

```bash
nmap -T2 -sV -p 22,80,443 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：同一目标 `-T1` 与 `-T4` 的两次扫描，输出**内容相同但结尾 `scanned in <秒>` 差异明显**的对照，用于说明 `-T` 只改变节奏，不改变结果。

#### 结果判读：六档到底差在哪

Nmap 的 `-T` 不是"速度档位"这么简单，它同时改了**超时、重试、并发、扫描延迟**四组参数：

| 模板 | 名称 | 并发探测 | 初始超时 | 最大重试 | 扫描延迟 | 现实耗时（相对） |
| --- | --- | --- | --- | --- | --- | --- |
| `-T0` | Paranoid | 1 | 5 分钟 | 5 | 5 分钟 | 极端慢，几小时起 |
| `-T1` | Sneaky | 1 | 15 秒 | 5 | 15 秒 | 很慢 |
| `-T2` | Polite | 1 | 1 秒 | 3 | 0.4 秒 | 慢但可用 |
| `-T3` | Normal | 6 | 1 秒 | 3 | 10 毫秒 | 默认档 |
| `-T4` | Aggressive | 10 | 1.25 秒 | 2 | 0 | 快，**推荐上限** |
| `-T5` | Insane | 16 | 0.3 秒 | 1 | 0 | 极快，**易误判** |

> 表中数值为 Nmap 官方文档公布的定时模板参数；不同版本可能有细微调整【待核实：以 `nmap --help` 与你所用版本的 `nmap-services`/定时模板说明为准】。

#### 注意事项

| 档位 | 什么时候用 | 代价 |
| --- | --- | --- |
| `-T0` / `-T1` | 教学演示"慢扫描"、极端敏感的授权测试 | 慢到不实用；**且"慢"≠"隐蔽"**，见下 |
| `-T2` | 生产环境、有监控的目标 | 时间成本高 |
| `-T3` | 默认，不确定时用它 | 平衡 |
| `-T4` | 局域网、自己靶场、时间紧的授权测试 | 可能丢包导致 `filtered` 增多 |
| `-T5` | **基本不要用** | 超时太短，会把慢服务误判为 `filtered` |

> [!WARNING]
> **`-T1` 不是"隐蔽模式"。** 它只是"慢"，而慢扫描在某些 IDS 看来更可疑（低频长时扫描是典型的 APT 特征）。真正的隐蔽来自流量整形、源地址分散与授权下的白名单，而不是 `-T` 档位。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| `-T4` 后 `filtered` 变多 | 降到 `-T3` 或 `-T2`。丢包会把 `open` 误判成 `filtered` |
| 太慢跑不完 | 先用 `--min-rate` 精确控速，而不是直接上 `-T5` |
| 目标有 WAF/IPS | `-T2` + `--scan-delay`，并降低端口数量 |

### 7.1.2 `--min-rate`：每秒最少发包数

#### 命令

```bash
nmap --min-rate <n> <目标IP>
```

#### 适用场景

想要**可预测的扫描时长**，或反过来想要**明确的速率上限**以保证礼貌。

#### 示例

```bash
# 至少每秒 1000 个包
nmap -Pn -p- -T4 --min-rate 1000 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：同一全端口扫描在 `--min-rate 100` 与 `--min-rate 1000` 下的耗时对照（须注明靶场环境与网段，否则耗时数字无参考价值）。

#### 结果判读

`--min-rate` 是**下限**，不是上限。Nmap 会尽量不低于这个速率。

- 设太小（如 5）：扫描慢得没必要；
- 设太大（如 10000）：丢包率上升，`filtered`/`open|filtered` 误判增多。

**经验值**：局域网单机 `1000` 左右合适；跨公网 `100–300`；有 IDS 的生产环境 `10–50`。

#### 注意事项

- 想要**上限**用 `--max-rate`（两者可同时给，形成区间）。
- `--min-rate` 与 `-T` 冲突时，显式参数优先。
- 速率过高会触发目标侧的 SYN flood 防护，表现为"扫到一半全部 filtered"。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 扫描中途结果突然全 `filtered` | 你可能被限速/封禁了。**停止**，降速重试，或联系授权方加白名单 |
| 想固定总时长 | 用 `--min-rate` 反推：`总端口数 / 目标秒数 ≈ 速率` |

### 7.1.3 `--max-retries`：最大重试次数

#### 命令

```bash
nmap --max-retries <n> <目标IP>
```

#### 适用场景

远端丢包严重导致扫描极慢，或想快速得到"大致结果"。

#### 示例

```bash
nmap -sU --top-ports 50 --max-retries 1 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：UDP 扫描在默认重试与 `--max-retries 1` 下的耗时对比，用于说明"UDP 扫描的慢主要来自重试"。

#### 结果判读

- 重试次数越少，越快，但**越容易把 `open` 误判成 `filtered`**（响应慢被当成没响应）。
- `--max-retries 0` 表示不重试，误判率最高。

#### 注意事项

- 对 UDP 扫描效果最明显（UDP 本来就靠超时判定）。
- 与 `--host-timeout` 配合能有效控制总时长。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 降重试后出现大量 `filtered` | 说明链路质量差，加回来重新确认关键端口 |

### 7.1.4 `--host-timeout`：单主机超时

#### 命令

```bash
nmap --host-timeout <时间> <目标网段>
```

#### 适用场景

扫一个网段，个别主机卡住导致整体拖很久。给每台主机设个上限，超时就跳过。

#### 示例

```bash
nmap -sV --host-timeout 5m -F 192.0.2.0/28
```

时间单位可写 `30s`、`5m`、`1h`，也可以只写数字（单位秒）。

#### 示例输出

【待补充示例输出】建议补充：网段扫描中出现 `Skipping host 192.0.2.x due to host timeout` 或结尾统计里被跳过主机的提示行，用于说明"超时的机器不会给结果，但扫描会继续"。

#### 结果判读

超时被跳过的主机 **不会出现在结果里**，而且**不会有明显错误提示**——这是它的坑。你会以为"这台没端口"，实际是"没扫完"。

#### 注意事项

| 坑 | 说明 |
| --- | --- |
| 静默跳过 | 必须自己在结尾统计或 `-v` 输出里核对目标数量 |
| 设太短 | `-sV` + `-p-` 的组合很容易被 5m 砍断 |
| 与 `--max-retries` 重复 | 两者都在控时长，选一个主要手段即可 |

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 有主机被跳过 | 单独对它跑，不加 `--host-timeout`，或放宽到 `30m` |
| 大量主机被跳过 | 说明网段里有设备在拖慢整体，改用 `-Pn` + 小端口集分批 |

### 7.1.5 其他节奏参数

| 参数 | 作用 | 典型用法 |
| --- | --- | --- |
| `--max-rate <n>` | 每秒最多发包数（上限） | `--max-rate 100` 做礼貌扫描 |
| `--scan-delay <时间>` | 两个探测包之间的固定间隔 | `--scan-delay 1s` 避开速率检测 |
| `--max-scan-delay <时间>` | 动态延迟的上限 | 配合 `-T4` 防止自动加速过头 |
| `--min-hostgroup <n>` / `--max-hostgroup <n>` | 并行扫描的主机数 | 网段扫描时控制并发 |
| `--stats-every <时间>` | 定期打印进度 | `--stats-every 10s`，长扫描时确认没死 |

**`--stats-every` 值得单独提一句**：`-p-` 这种长扫描，没有进度输出时你根本分不清"还在跑"和"卡死了"。加上它，每 10 秒一行统计，心里有底。

## 7.2 规避与欺骗

> [!WARNING]
> 本节所有技术都属于**主动规避安全检测**的手段。
>
> - 在**你自己拥有或明确授权**的环境里，它们是合法的测试项（用于验证 IDS/防火墙有效性）。
> - 在**任何其他环境**里使用，在很多司法辖区会被认定为"规避安全措施"，属于加重情节，即使你只扫了端口。
> - 规避技术会让**你自己的流量也变得不可信**：丢了包你不知道是防火墙拦的还是你自己搞坏的。
>
> 结论：**初学阶段不必花时间在这上面。** 先把 [08 章](08-workflow.md) 的流程练熟。

### 7.2.1 `-D <诱饵IP>`：诱饵扫描

#### 命令

```bash
nmap -D <诱饵IP1>,<诱饵IP2>,ME <目标IP>
```

#### 适用场景

授权范围内验证"目标能否从一堆源地址中分辨出真正的扫描者"。

#### 示例

```bash
nmap -D 198.51.100.7,198.51.100.8,ME -p 80,443 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：在自建实验环境中，用 `tcpdump` 在目标侧抓包，展示同一批 SYN 包来自多个源地址的**抓包证据**（不是 Nmap 输出），因为 `-D` 的效果只能在目标侧或中间设备上观测。

#### 结果判读

`-D` 不会改变 Nmap 的输出。**它的效果只能在目标侧/IDS 侧观测**——所以从扫描者的屏幕上是看不出成功与否的。这也是它常被误解的原因。

#### 注意事项

| 项 | 说明 |
| --- | --- |
| 诱饵地址必须真实存在且路由可达 | 用一个不存在的地址，会让目标收到不可达 ICMP，反而暴露 |
| `ME` 表示"把你自己的真实地址也放进去" | 不加 `ME` 就完全不发你自己的地址，收不到回应 |
| 对有状态防火墙无效 | 防火墙只认已建立连接的源，诱饵包会被直接丢 |
| 合规 | 用别人的 IP 做诱饵，等于**冒用第三方地址**，可能给无关方带来麻烦 |
| 权限 | 需要 root |

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 扫描结果变差 | 正常，诱饵会引入额外噪音。**优先保证结果准确，再谈规避** |
| 目标是验证 IDS | 用抓包 + IDS 日志作为证据，不要只看 Nmap 输出 |

### 7.2.2 `-S <IP>`：伪造源地址

#### 命令

```bash
nmap -S <伪造源IP> -e <网卡> <目标IP>
```

#### 适用场景

**几乎没有正当场景。** 唯一合理用途是在完全隔离的实验室里演示"为什么源地址伪造在 TCP 上不可行"。

#### 示例

```bash
nmap -S 198.51.100.99 -e eth0 -Pn 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：在隔离实验网中，`-S` 指定一个不属于本机的地址后，扫描结果全部为 `filtered` 的输出，用于说明"你收不到回应，因为回包发到了别人的机器"。

#### 结果判读

结果通常是**全 `filtered`**。原因很简单：

```text
你 --SYN(源=198.51.100.99)--> 目标
目标 --SYN/ACK--> 198.51.100.99   ← 回包不回到你这里
```

TCP 需要双向。源地址一伪造，你就**收不到任何回应**，扫描必然失败。

#### 注意事项

> [!WARNING]
>
> - `-S` 需要指定出口网卡 `-e`，且通常需要 root。
> - **它会破坏整个扫描**（收不到回包），除非你同时能嗅探到回包路径（这需要处在网络路径上）。
> - 冒用他人 IP 地址在几乎所有司法辖区都是违法或至少违规行为，与"有没有授权扫目标"无关。
> - 本书**不建议**在任何真实环境中使用该参数，包括授权测试。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 你真的需要"换源地址" | 正确的做法是**换出口**（VPN、跳板机、云主机），而不是伪造 IP。且需授权方同意该出口地址 |

### 7.2.3 `-f`：报文分片

#### 命令

```bash
nmap -f <目标IP>
nmap -f -f <目标IP>          # 更小的分片（8 字节）
nmap --mtu <n> <目标IP>      # 自定义 MTU
```

#### 适用场景

验证"目标的老式包过滤防火墙能否正确处理分片包"。

#### 示例

```bash
nmap -f -p 80,443 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：同一目标 `-f` 前后的对照输出，以及在目标侧 `tcpdump` 看到的分片包证据。

#### 结果判读

现代环境里 `-f` 通常**没有效果**：

| 环境 | `-f` 的表现 |
| --- | --- |
| 现代有状态防火墙 | 自动重组分片，无影响 |
| 云安全组 | 多数直接丢弃或重组 |
| 老式无状态 ACL | 可能绕过，这是它唯一有效的场景 |
| 某些 IDS | 把分片包视为**明确的攻击特征** |

#### 注意事项

- 分片会增加包数量，扫描变慢。
- 多数现代网络对分片的处理是"重组后再检查"，所以它**不提高成功率**。
- `--mtu` 的值必须是 8 的倍数，否则 Nmap 报错。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 加了 `-f` 没变化 | 正常。去掉它，减少变量 |

### 7.2.4 `--data-length <n>`：填充随机数据

#### 命令

```bash
nmap --data-length <n> <目标IP>
```

#### 适用场景

把探测包填充到指定长度，避免因"包大小过于规律"被特征匹配命中。

#### 示例

```bash
nmap --data-length 25 -p 80,443 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：目标侧抓包对比 `--data-length 25` 与默认时 TCP payload 长度的差异。

#### 结果判读

只改变包长，不改变判定逻辑。**对结果没有影响**，只影响流量特征。

#### 注意事项

- 填充长度过大会导致分片，可能反而触发更多告警。
- 与 `-f` 组合时行为复杂，不建议叠加。
- 它对"规避"的作用被严重高估：现代检测看的是行为模式（端口序列、时序），不是单个包的长度。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 只是想让流量"不像扫描器" | 更有效的是降速 + 缩小端口范围 + 分散时间，而不是改包长 |

## 7.3 输出与保存

### 7.3.1 `-oN`：标准文本

#### 命令

```bash
nmap -oN <文件名> <目标IP>
```

#### 适用场景

要给人看、要贴进报告、要存档。

#### 示例

```bash
nmap -sV -oN scan-192.0.2.10.txt 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：`-oN` 生成的文件内容，重点说明它**与终端输出几乎相同，但会包含 `# Nmap <版本> scan initiated <时间>` 这样的头部注释**，用于事后证明扫描时间。

#### 结果判读

`-oN` 会加上头部与结尾注释，这两行是**证据价值最高**的部分：

```text
# Nmap <版本> scan initiated <日期时间> as: nmap -sV -oN scan-192.0.2.10.txt 192.0.2.10
# Nmap done at <日期时间> -- 1 IP address (1 host up) scanned in <秒> seconds
```

注意第一行记录了**完整命令行**。这是复现的依据，也是"我扫了什么"的自证。

#### 注意事项

- 文件名含空格要加引号。
- `-oN` 的格式是给人读的，**不适合脚本解析**（列宽会变）。
- 覆盖同名文件时 Nmap 会直接覆盖，无提示。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 要交给别人复核 | `-oN` + `-oX` 一起给 |
| 后续要用脚本处理 | 用 `-oG` 或 `-oX` |

### 7.3.2 `-oX`：XML

#### 命令

```bash
nmap -oX <文件名> <目标IP>
```

#### 适用场景

要喂给其他工具（Zenmap、报告生成器、自建解析脚本）、要做长期资产对比。

#### 示例

```bash
nmap -sV -oX scan-192.0.2.10.xml 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：一份最小的 `-oX` 输出骨架（`<nmaprun>` → `<host>` → `<ports>` → `<port>` → `<state>` /
`<service>`），用于说明 XML 的层级结构，便于写解析脚本。

结构示意：

```xml
<?xml version="1.0"?>
<nmaprun scanner="nmap" args="nmap -sV -oX scan.xml 192.0.2.10" start="..." version="...">
  <host>
    <status state="up" reason="..."/>
    <address addr="192.0.2.10" addrtype="ipv4"/>
    <ports>
      <port protocol="tcp" portid="443">
        <state state="open" reason="syn-ack"/>
        <service name="https" product="..." version="..."/>
      </port>
    </ports>
  </host>
  <runstats>...</runstats>
</nmaprun>
```

> 属性值为示意，实际内容以你的扫描结果为准。`version` 属性不要照抄。

#### 结果判读

XML 是**所有输出格式里信息最全的**：包含 `reason`（判定原因）、`service` 的 CPE、脚本结果的完整结构化数据、运行统计。

常用提取方式：

```bash
# 用 grep 快速找开放端口（粗糙但够用）
grep -o 'portid="[0-9]*"' scan-192.0.2.10.xml

# 用 python 解析（推荐，需 lxml 或 xml.etree）
python3 -c "
import xml.etree.ElementTree as ET
for h in ET.parse('scan-192.0.2.10.xml').iter('host'):
    addr = h.find('address').get('addr')
    for p in h.iter('port'):
        s = p.find('state').get('state')
        if s == 'open':
            print(addr, p.get('portid'), p.find('service').get('name'))
"
```

#### 注意事项

- XML 用于程序消费，不要试图直接读它。
- 版本升级时 XML schema 可能变化，长期脚本要做容错。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 要对比两次扫描 | 两次都用 `-oX`，再用 Zenmap 的 Compare Results 或自己 diff |
| 要生成报告 | 从 XML 提数据，模板渲染，别手工抄 |

### 7.3.3 `-oG`：grep 友好格式

#### 命令

```bash
nmap -oG <文件名> <目标IP>
```

#### 适用场景

要用 `grep` / `awk` / `cut` 一行行处理结果。

#### 示例

```bash
nmap -p 80,443 -oG scan.gnmap 192.0.2.0/28

# 提取所有开放 443 的主机
grep "443/open" scan.gnmap | awk '{print $2}'
```

#### 示例输出

【待补充示例输出】建议补充：一段真实 `.gnmap` 内容（每台主机一行，含 `Ports:` 列表），用于说明"一台主机一行"这个特征为什么适合 `awk`。

格式示意：

```text
Host: 192.0.2.10 (host-a.example.com)  Status: Up
Host: 192.0.2.10 (host-a.example.com)  Ports: 80/open/tcp//http//, 443/open/tcp//https//  Ignored State: closed (998)
```

#### 结果判读

一台主机占一行，字段用制表符分隔，`Ports:` 后面是 `端口/状态/协议//服务//版本/` 的斜杠分隔串（空字段就是空）。

**注意**：`-oG` 已被上游标记为**过时格式**，新脚本建议直接用 `-oX`。但它对 shell 处理确实方便，仍有大量存量用法。

#### 注意事项

- 服务名与版本字段可能含逗号或空格，用 `cut` 容易切错，**优先用 `awk` 精确取列**。
- 空字段会连续出现 `//`，解析时不要用固定分隔符计数。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 只是临时筛一下 | `-oG` + `grep` 最快 |
| 要做长期维护的解析 | 换 `-oX` |

### 7.3.4 `-oA <前缀名>`：一次存三种

#### 命令

```bash
nmap -oA <文件名> <目标IP>
```

#### 适用场景

**默认就该用这个。** 一次产出 `.nmap`（文本）、`.xml`（XML）、`.gnmap`（grep），后续无论要给人看还是给机器读都有。

#### 示例

```bash
nmap -sV -sC -oA scan-192.0.2.10 192.0.2.10
```

#### 示例输出

执行后目录里会出现三个文件：

```text
scan-192.0.2.10.nmap
scan-192.0.2.10.xml
scan-192.0.2.10.gnmap
```

#### 结果判读

`-oA` 的参数是**前缀**，不是文件名——你写 `scan-192.0.2.10`，Nmap 自动加扩展名。

#### 注意事项

| 坑 | 说明 |
| --- | --- |
| 前缀含路径 | `-oA out/scan` 要求 `out/` 目录已存在 |
| 覆盖 | 同名文件直接覆盖，无提示 |
| 含空格 | 加引号 |
| 命名建议 | 用 `日期-目标-用途`，如 `20260101-192.0.2.10-web`，否则一周后你自己也认不出 |

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 要长期跟踪资产变化 | 建立固定命名规范 + 定期重扫 + diff |
| 要提交给客户 | `.nmap` 给人看，`.xml` 给工具，两个都给 |

### 7.3.5 详细程度：`-v` / `-vv` / `-d`

| 参数 | 作用 | 什么时候用 |
| --- | --- | --- |
| 默认 | 只显示开放端口，隐藏 `closed` 的统计行 | 日常 |
| `-v` | 详细：显示被隐藏端口的统计、更多状态行 | 想确认"到底扫了多少端口" |
| `-vv` | 更详细：实时打印每个探测 | 排错、教学演示 |
| `-d` / `-d2`... | 调试：打印内部决策 | **只在排错时用**，输出极其冗长 |

#### 示例

```bash
nmap -v -p 1-100 192.0.2.10
nmap -vv -sn 192.0.2.0/28
```

#### 示例输出

【待补充示例输出】建议补充：同一目标默认与 `-v` 的输出差异，重点展示 `Not shown: N closed tcp ports` 这类统计行在 `-v` 下的变化。

#### 结果判读

`-v` 最实用的地方是**让你看到"被隐藏的部分"**：

```text
Not shown: 997 closed tcp ports (reset)
```

这一行告诉你 997 个端口是 `closed`（收到 RST），而不是 `filtered`。**有这一行 = 没有拦截；写成 `filtered` = 有拦截。**

#### 注意事项

- `-vv` 的输出量可能上百倍，**不要对网段用**。
- `-d` 是给开发者看的，里面全是内部状态，初学者读它只会更困惑。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 不确定扫了多少端口 | `-v` 看 `Not shown` 行 |
| 扫描行为诡异 | `-d2` 抓一段输出，配合 `--reason` 分析 |

### 7.3.6 `--reason` 与 `--open`

| 参数 | 作用 | 典型用途 |
| --- | --- | --- |
| `--reason` | 在每个端口后加一列 `REASON`，说明判定依据 | 排错、写报告时证明"为什么判为 open" |
| `--open` | 只显示 `open` / `open\|filtered` / `unfiltered` 的端口 | 大网段扫描，过滤噪音 |

#### 示例

```bash
nmap -sS --reason -p 22,80,443 192.0.2.10
nmap -Pn -p- --open 192.0.2.10
```

#### 示例输出

【待补充示例输出】建议补充：`--reason` 输出的 `REASON` 列，至少包含 `syn-ack`、`reset`、`no-response` 三种取值，用于建立"状态 ↔ 原因"的对应关系。

#### 结果判读

`REASON` 列的常见取值：

| 取值 | 对应状态 | 含义 |
| --- | --- | --- |
| `syn-ack` | `open` | 收到 SYN/ACK |
| `reset` | `closed` | 收到 RST |
| `no-response` | `filtered` / `open\|filtered` | 什么都没收到 |
| `host-unreachable` | `filtered` | ICMP 主机不可达 |
| `net-unreachable` | `filtered` | ICMP 网络不可达 |
| `admin-prohibited` | `filtered` | ICMP 被管理员禁止 |

**`--reason` 是排错的第一把手**：`filtered` 到底是"被 DROP 了"（`no-response`）还是"网络不通"（`net-unreachable`），一眼就能分清。

#### 注意事项

- `--open` 会**隐藏 closed 与 filtered**，排查"为什么连不上"时不要用它。
- `--open` 与 `-v` 的 `Not shown` 行配合，报告里更有说服力。

#### 下一步决策

| 情况 | 下一步 |
| --- | --- |
| 报告要"只列开放端口" | `--open` |
| 排查连不通 | 去掉 `--open`，加 `--reason` |

## 7.4 参数组合速查

| 目的 | 组合 |
| --- | --- |
| 快速初筛 | `-F -T4 -n` |
| 中等深度 | `-sV -p <端口列表> -T4` |
| 完整单机 | `-sV -sC -O -p- -T4 --min-rate 1000 -oA <文件名>` |
| 大网段存活 | `-sn -T4 -n --min-rate 500` |
| 礼貌扫描（生产） | `-T2 --max-rate 100 --scan-delay 200ms` |
| 长扫描不迷路 | `--stats-every 10s -v` |
| 排错专用 | `--reason -v -d2`（只对单端口） |
